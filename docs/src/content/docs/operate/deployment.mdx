Use Docker Compose to run the city plugin on your server. Build one image for the API and workers, then check API readiness and worker heartbeats.

Complete [deployment preparation](../requirements/) first. Compose starts Redis. The city plugin includes all its data and needs no additional data service.

<Steps>

1. ## Prepare the example configuration <span id="1-prepare-the-example-configuration"></span>

   From the repository root:

   ```sh
   cd examples/lyra-deployment
   cp .env.example .env
   ```

   Set `api.public_base_url` in the example’s `lyra.toml` to the server URL your clients can reach.

   For local development, the public URL can be `http://localhost:5219`. For remote use, configure your public HTTPS URL and [reverse proxy](../configuration/#configure-a-reverse-proxy).

   The example’s Redis URL, `redis://redis:6379/0`, matches its Compose service. Its plugin configuration enables `lyra-city-example`, including the bundled city dataset. The first server job uses `street-1` from this provider.

   If you completed the city tutorial in this checkout, the default `CITY_PLUGIN_SOURCE=../city-plugin` includes your changes. For a separate copy, set `CITY_PLUGIN_SOURCE` in `.env` to that project’s absolute directory. [Export your entry-point factory](../../plugins/tutorial/package/) before building the deployment image.

1. ## Supply credentials <span id="2-supply-credentials"></span>

   Set these variables in `.env`:

   ```text
   LYRA_AGENT_API_KEY=your_random_agent_secret_here
   LYRA_ADMIN_API_KEY=your_different_random_admin_secret_here
   ```

   Keep `.env` outside version control. The example mounts configuration read-only and includes the city data in the plugin package. Only API services receive API keys.

1. ## Validate the TOML <span id="3-validate-the-toml"></span>

   From `examples/lyra-deployment`, validate the configuration using the repository’s Python environment.

   ```sh
   uv run --project ../.. lyra-admin config validate lyra.toml
   ```

   This offline check validates the file’s syntax and field values. Check service health after startup.

1. ## Build and start <span id="4-build-and-start"></span>

   From `examples/lyra-deployment`:

   ```sh
   docker compose up -d --build
   ```

   The production build installs the locked dependencies into one image for API and workers. At startup, both processes import enabled distributions through their entry-point factories and compile the live definitions.

   Ensure both processes can import every plugin dependency. Assign them the same immutable `build_revision`; see [build configuration](../configuration/#assign-a-deployment-build-revision).

   The example starts six worker processes that read from the same queue, `lyra`. Each process can run one graph at a time. To change the queue or process count, set `jobs.queue` or `worker.concurrency` in the [shared configuration](../configuration/#place-configuration-and-secrets).

1. ## Check API readiness and worker heartbeats <span id="5-check-api-readiness-and-worker-heartbeats"></span>

   Check the API health endpoints and read the most recent startup logs for both services.

   ```sh
   curl -i http://localhost:5219/live
   curl -i http://localhost:5219/ready
   docker compose logs --tail=100 api worker
   ```

   Expect HTTP 200 from both endpoints. A successful `/live` check means the API is running. A successful `/ready` check means it can reach Redis.

   Check for active workers from the API container, where Compose sets the administrator key.

   ```sh
   docker compose exec api lyra-admin --json queue show
   ```

   Look for the queue name `lyra` and at least one worker ID in `observed_workers`. An empty list means no worker has reported a fresh heartbeat on that queue.

   To verify a complete calculation, follow [Run your first server job](../../quickstart/).

</Steps>

## Know where files live

All application containers share a writable `/lyra_data` volume:

```text
/lyra_data/
  config/lyra.toml
  results.sqlite3
  cache/jobs/
  logs/
```

The configuration file mounts read-only at `config/lyra.toml`. Both example configurations select `/lyra_data/results.sqlite3`. Give the account running Lyra write access to the database’s parent directory for SQLite journal files.

Preserve the data volume across restarts and deployments because Lyra retains written results indefinitely. Enabled plugins and their entry points belong to the image’s Python environment.

Use [updates](../updates/) for changes to a running deployment and [troubleshooting](../troubleshooting/) if startup or the first job fails.
