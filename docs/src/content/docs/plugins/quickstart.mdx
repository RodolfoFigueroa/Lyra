Inspect a completed plugin when reviewing a package or diagnosing a declaration. For a guided build, use [the city tutorial](../tutorial/). Work from the standalone `examples/city-plugin` project with its environment prepared.

## Inspect the factory

The configured factory is `city_example:create_plugin`. It returns a definition containing the metrics, location operation, and one provider resource. You can inspect it without acquiring data:

```python
from city_example import create_plugin

plugin = create_plugin()
print(plugin.describe("city_street_maintenance"))
```

Node registration is explicit. Inspect the graph's dependencies and contracts rather than assuming every decorated sibling function is registered.

## Check the package metadata

The project declares its own dependencies, includes `city_example/data/city.json`, and installs the generated manifest at `share/lyra/plugins/lyra-city-example/lyra.plugin.json`. The distribution name differs from the import package name. [Packaging](../publish-and-debug/) explains normalization and version agreement.

## Generate and inspect the manifest

Run these commands from the example project:

```sh
uv run lyra-plugin build-manifest
uv run lyra-plugin check-manifest
uv run lyra-plugin describe city_street_maintenance
uv run lyra-plugin diagram --detailed --output graph.mmd
```

The application reads the saved manifest without importing handlers. Workers compare it with imported definitions. Generation and inspection need no source credentials or services.

## Test before handoff

Run [isolated plugin tests](../testing/) and provide the operator a known request with expected results. The city example's default threshold produces street workloads of 100 m, 0 m, and 300 m. Operators [enable the installed distribution](../../operate/plugins/) separately.
