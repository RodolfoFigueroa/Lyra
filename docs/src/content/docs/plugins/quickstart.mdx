Inspect a completed plugin to check which calculations it exposes and what inputs they accept. This helps you review a package before enabling it or investigate why a metric is missing. For a guided build, use [the city tutorial](../tutorial/). Work from the standalone `examples/city-plugin` project with its environment prepared.

## Inspect the factory

The factory is the function that returns the plugin’s registered calculations and data provider. This package configures `city_example:create_plugin` as its factory. Call it and inspect the maintenance metric without loading street data:

```python
from city_example import create_plugin

plugin = create_plugin()
print(plugin.describe("city_street_maintenance"))
```

Check which metrics and dependencies the returned definition includes. Adding `@metric` to a function does not register it automatically; the factory must include it.

## Check the package metadata

The project declares its own dependencies, includes `city_example/data/city.json`, and installs the generated manifest at `share/lyra/plugins/lyra-city-example/lyra.plugin.json`. The installed distribution is named `lyra-city-example`; Python imports use `city_example`. [Packaging](../publish-and-debug/) explains the naming rules and which version declarations must match.

## Generate and inspect the manifest

The manifest saves the plugin’s declarations so the application can inspect them without importing calculation code. From the example project, generate that file, check that it matches the definitions, describe the maintenance metric, and save a diagram of the registered dependencies:

```sh
uv run lyra-plugin build-manifest
uv run lyra-plugin check-manifest
uv run lyra-plugin describe city_street_maintenance
uv run lyra-plugin diagram --detailed --output graph.mmd
```

The application reads the saved manifest without importing handlers. Workers compare the saved declarations with the definitions they load before running calculations. Generation and inspection need no source credentials or services.

## Test before handoff

Run [isolated plugin tests](../testing/) and provide the operator a known request with expected results. The city example’s default threshold produces street workloads of 100 m, 0 m, and 300 m. Operators [enable the installed distribution](../../operate/plugins/) separately.
