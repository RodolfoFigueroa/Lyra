A plugin is an installable Python package with one `PluginDefinition`, decorated
metric and dataset functions, and a generated root `lyra.plugin.json`. Python definitions
are authoritative; never edit the manifest directly.

To adapt an existing workflow with a coding agent, use the portable skill described
in [Agent-assisted authoring](../agent-assisted-authoring/).

## Start from the executable example

The repository's `examples/lyra-plugin` package is used by this guide and by the
test suite:

  smoke_plugin/

## Generate the manifest

From the plugin project:

```bash
uv run lyra-plugin build-manifest
uv run lyra-plugin check-manifest
```

Commit `lyra.plugin.json`. The API reads it without importing plugin code;
workers compare it with the imported registry and reject stale artifacts.

To rebuild and validate the manifest before every commit, add the local Lyra
hook to the plugin repository and install pre-commit's Git integration:

```bash
uv add --dev pre-commit
uv run lyra-plugin add-pre-commit-hook
uv run pre-commit install
```

The command creates or updates `.pre-commit-config.yaml` without replacing
existing hooks. If a commit regenerates `lyra.plugin.json`, stage the updated
file and commit again. Running the command more than once leaves an existing
Lyra hook, including any local customization, unchanged.

## Test and connect

Test the decorated function and manifest before publishing:

```bash
uv run lyra-plugin check-manifest
uv run lyra-plugin describe
uv run python -c "from smoke_plugin.plugin import create_plugin; print(create_plugin().metric_names)"
uv run pytest
```

Include the manifest as package shared data, as shown in the example
`pyproject.toml`. Add the package to your deployment project, lock its dependencies,
and rebuild the image. Select its distribution under `[[plugins.installed]]` in
`lyra.toml`, then recreate the API and workers together. The
[publishing guide](../publish-and-debug/) covers packaging, queues, and diagnosis.
