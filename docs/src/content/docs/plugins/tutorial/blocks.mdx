A city report may need a workload total for each block, while your calculation currently returns individual streets. You’ll let callers select blocks, find their streets, and divide the street workload between those blocks. Start with [your graph module](../dependencies/) and its passing comparison test; you’ll extend `city_example/tutorial.py`.

The membership table records which streets belong to each block and what share each block receives. It serves two purposes: finding streets to calculate on, and assigning their results to blocks. Lyra calculates maintenance for each shared street once. Your block calculation then divides that result using the membership shares.

<BlockWorkloadDiagram />

For `block-1` and `block-2`, membership identifies all three streets. The existing maintenance metric calculates their workload, then the block metric combines those results with the membership weights. The final table contains one row per requested block.

1. ## Import the new graph components

   Add these imports to `city_example/tutorial.py`, keeping the previous imports and handlers:

   ```python title="city_example/tutorial.py"

   from lyra.sdk import Input, LocationContext, LocationDependency, location_operation
   from city_example.data import load_city
   from city_example.schemas import BLOCKS, MEMBERSHIP, STREET_SCHEMA, SUMMARY
   ```

   The supplied membership data assigns `street-1` entirely to `block-1`, splits `street-2` equally between two blocks, and assigns `street-3` entirely to `block-2`. The example data defines these shares; the calculation does not infer them from intersections.

1. ## Read membership for the selected blocks

   Add a metric that returns membership rows for the requested blocks. Marking it private keeps this intermediate table out of direct public requests. Its block input also records which block geometry and membership revision the calculation depends on:

   The returned rows contain `block_id`, `street_id`, and `weight`. An empty selection of membership rows retains those columns and their data types.

1. ## Derive complete street observations

   The maintenance metric needs street geometry and properties, while membership contains only IDs and shares. Add a location operation, a function that supplies locations to another calculation. This one extracts the street IDs and asks the provider to load their data:

   ```python title="city_example/tutorial.py"
   @location_operation(
       name="city_streets_for_blocks", canonical=False,
       description="Select each street belonging to any supplied block once.",
       locations={"blocks": BLOCKS},
       inputs={
           "membership": Dependency(
               "membership",
               producer="city_street_membership",
           ),
       },
       output=STREET_SCHEMA, output_contract=STREETS,
   )
   def streets_for_blocks(
       blocks: Locations, membership: pd.DataFrame, context: LocationContext
   ) -> gpd.GeoDataFrame:
       del blocks
       ids = list(dict.fromkeys(membership.street_id))
       return context.resolve_locations(
           "example:city", "street", ids,
       ).to_geodataframe()
   ```

   `LocationContext` gives the operation access to the provider Lyra manages for this run. Removing duplicate IDs loads `street-2` once, while the membership table keeps its separate shares for both blocks. Keep `canonical=False` here: this operation is an internal step of the block calculation. Chapter six makes it available for callers selecting blocks for a street report.

1. ## Bind streets to the maintenance calculation

   Connect the block request to the street calculation. `selected_streets` describes how to obtain streets from blocks; `block_inputs` requests both the resulting street maintenance table and the membership table:

1. ## Calculate the weighted block summary

   Append the block metric’s decorator. `SUMMARY` declares `block_id`, `allocated_length_m`, and `maintenance_length_m`, with one row per block:

   ```python title="city_example/tutorial.py"
   @metric(
       name="city_block_maintenance",
       description="Allocated street lengths and maintenance workload per block.",
       locations={"blocks": BLOCKS}, inputs=block_inputs,
       outputs={"summary": SUMMARY},
   )
   ```

   Append the handler immediately after its decorator. Merge into a new table, apply the weights, and restore the requested block order:

   ```python title="city_example/tutorial.py" {9-13,15-17}
   def block_maintenance(
       blocks: Locations, parameters: MaintenanceParameters,
       maintenance: pd.DataFrame, membership: pd.DataFrame,
   ) -> pd.DataFrame:
       del parameters
       joined = membership.merge(
           maintenance, on="street_id", validate="many_to_one",
       )
       joined["allocated_length_m"] = joined.length_m * joined.weight
       joined["maintenance_length_m"] = joined.maintenance_length_m * joined.weight
       totals = joined.groupby("block_id")[
           ["allocated_length_m", "maintenance_length_m"]
       ].sum()
       return (
           totals.reindex(list(blocks.ids), fill_value=0.0)
           .rename_axis("block_id")
           .reset_index()
       )
   ```

   Joining on `street_id` attaches each street’s result to its block shares, regardless of row order. Multiplying by `weight` assigns the correct share before summing by block. Reindexing keeps every requested block, including a zero row for `block-empty` when no streets exist.

   The handler does not use `parameters` directly because the maintenance dependency has already applied the threshold. This keeps the maintenance decision in one place.

   Replace the existing `create_plugin()` with this factory:


   Create `block_report.py` in the project root and run your new public metric:

   ```python title="block_report.py"
   from lyra.runtime.local import LocalRunner
   from city_example.tutorial import create_plugin

   runner = LocalRunner.from_definitions({"city": create_plugin()})
   tables = runner.run("city_block_maintenance", {
       "blocks": {
           "collection": "example:city", "unit_type": "block",
           "ids": ["block-1", "block-2", "block-empty"],
       },
   })
   print(tables["summary"].to_dict("records"))
   ```

   Run `uv run python block_report.py`. The supplied reference command is `uv run python -m city_example 5`. Both produce:

   | block_id | allocated_length_m | maintenance_length_m |
   | --- | --- | --- |
   | block-1 | 200.0 | 100.0 |
   | block-2 | 400.0 | 300.0 |
   | block-empty | 0.0 | 0.0 |

   `block-1` receives all 100 m of `street-1` and half of the 200 m `street-2`, for 200 m total. At the default threshold of 50, only `street-1` needs work, giving this block 100 m of maintenance. `block-2` receives the other 100 m share plus 300 m from `street-3`; only `street-3` needs work, giving 300 m of maintenance.

1. ## Test allocation and empty inputs

   Append this test to `tests/test_tutorial.py`. A threshold of 90 makes all three streets need work. This checks that the shared street contributes half its workload to each block rather than its full length to both:

   ```python title="tests/test_tutorial.py" {8,10-12}
   def test_shared_street_allocation():
       runner = LocalRunner.from_definitions({"city": create_plugin()})
       table = runner.run("city_block_maintenance", {
           "blocks": {
               "collection": "example:city", "unit_type": "block",
               "ids": ["block-2", "block-1"],
           },
           "parameters": {"condition_threshold": 90},
       })["summary"]
       assert table.block_id.tolist() == ["block-2", "block-1"]
       assert table.allocated_length_m.tolist() == [400.0, 200.0]
       assert table.maintenance_length_m.tolist() == [400.0, 200.0]
   ```

   Add a test for `block-empty`, which has no streets. The result should still include the block, with zero length and maintenance workload:

   ```python title="tests/test_tutorial.py" {8-10}
   def test_empty_block_summary():
       runner = LocalRunner.from_definitions({"city": create_plugin()})
       table = runner.run("city_block_maintenance", {"blocks": {
           "collection": "example:city", "unit_type": "block",
           "ids": ["block-empty"],
       }})["summary"]
       assert table.to_dict("records") == [{
           "block_id": "block-empty",
           "allocated_length_m": 0.0, "maintenance_length_m": 0.0,
       }]
   ```

   Run `uv run pytest tests/test_tutorial.py`. Continue to [accept block selections for street calculations](../canonical/), using the same operation for public selection.
