Let callers choose streets instead of always measuring the whole fixture. Start with [the first metric](../first-metric/). The provider supplied by this project resolves exact IDs from the same bundled data.

## Separate selections from resolved locations

A public selection contains a collection, unit type, and IDs. A provider resolves that selection into a `Locations` value containing geometry and properties. The handler receives resolved locations; callers supply IDs.

| Declaration | Purpose |
| --- | --- |
| `example:city` | Names the collection |
| `street` | Selects the entity type within the collection |
| `STREETS` | Binds the schema to the bundled source and geography |
| `CityLocationProvider` | Resolves the requested IDs into complete observations |

The provider declares its collection, executable output schemas, and source contracts:

<CodeExample path="examples/city-plugin/city_example/provider.py" region="provider" lang="python" />

Its `setup()` reads package data when execution first requests it. `resolve(contract, ids)` returns exactly the requested rows and reports unknown IDs. The runner owns resource setup and cleanup. Follow [provider implementation](../../location-providers/) when adapting this provider to your data.

## Register and run the provider

Append the factory that registers this metric and designates its provider resource:

<CodeExample path="examples/city-plugin/city_example/checkpoints.py" region="selected" lang="python" title="selected_metric.py" />

Append a request for two streets in a deliberate order:

```python title="selected_metric.py"
runner = LocalRunner.from_definitions({"city": selected_plugin()})
tables = runner.run(
    "city_street_lengths",
    {"streets": {
        "collection": "example:city",
        "unit_type": "street",
        "ids": ["street-3", "street-1"],
    }},
)
print(tables["lengths"].to_dict("records"))
```

Run `uv run python selected_metric.py`, or `uv run python -m city_example 2`. The output identifies `street-3` with length 300 m, followed by `street-1` with length 100 m. Duplicate requested IDs resolve once, preserving first-occurrence order. An unknown street fails execution with resolution context.

## Test selection order and duplicate IDs

Create `tests/test_selected_metric.py`. Request streets in a different order and repeat an ID:

```python title="tests/test_selected_metric.py"
from lyra.sdk import LocalRunner
from selected_metric import selected_plugin


def test_selection_preserves_first_occurrence_order():
    runner = LocalRunner.from_definitions({"city": selected_plugin()})
    table = runner.run("city_street_lengths", {
        "streets": {
            "collection": "example:city", "unit_type": "street",
            "ids": ["street-3", "street-1", "street-3"],
        },
    })["lengths"]
    assert table.street_id.tolist() == ["street-3", "street-1"]
    assert table.length_m.tolist() == [300.0, 100.0]
```

Run `uv run pytest tests/test_selected_metric.py`. The test checks the resolved input order as well as the measured values.
