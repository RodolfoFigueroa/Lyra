A report may cover only the streets someone wants to inspect. You’ll let callers supply street IDs, then use the project’s data provider to load those streets for your calculation. Start with [the first metric](../first-metric/); the result will contain only the requested streets, in their requested order.

<Steps>

1. ## Separate selections from resolved locations

   For `street-3`, the caller supplies an ID rather than sending its geometry. A provider is the object that looks up that ID and loads the geometry and properties your calculation needs. Lyra groups those rows in a `Locations` value and passes it to your metric function, also called a handler.

   The request also names a collection and a unit type so the provider knows which dataset and kind of feature to look up:

   | Declaration | Purpose |
   | --- | --- |
   | `example:city` | Identifies the bundled city dataset |
   | `street` | Requests streets within that dataset |
   | `STREETS` | Declares which street data the calculation accepts |
   | `CityLocationProvider` | Loads geometry and properties for the requested streets |

   The supplied provider declares its dataset, the columns it returns, and the source versions those rows belong to. This lets Lyra check that the data matches the metric’s requirements:

   <CodeExample path="examples/city-plugin/city_example/provider.py" region="provider" lang="python" meta="{10-14}" />

   Its `setup()` reads package data when execution first requests it. `resolve(contract, ids)` returns exactly the requested rows and reports unknown IDs. The runner initializes and closes the provider. Follow [provider implementation](../../location-providers/) when adapting this provider to your data.

1. ## Declare the location input

   Create `selected_metric.py` with the imports needed for this checkpoint:

   ```python title="selected_metric.py"
   import pandas as pd
   from lyra.data import Locations
   from lyra.runtime.local import LocalRunner
   from lyra.sdk import PluginDefinition, metric

   from city_example.calculations import calculate_lengths
   from city_example.provider import CityLocationProvider
   from city_example.schemas import LENGTHS, STREETS
   ```

   Append a handler accepting `streets` to `selected_metric.py`. Keep `first_metric.py` for the earlier test. The decorator connects the `streets` argument to `STREETS`, the declaration of the data it accepts:

   <CodeExample path="examples/city-plugin/city_example/metrics.py" region="lengths" lang="python" title="selected_metric.py" meta="{4-7,13}" />

   The underlying calculation still receives a GeoDataFrame. `to_geodataframe()` exports an independent frame with IDs, properties, and the declared coordinate reference system.

1. ## Register and run the provider

   Append the factory that registers this metric and tells Lyra to use `CityLocationProvider` when loading streets:

   <CodeExample path="examples/city-plugin/city_example/checkpoints.py" region="selected" lang="python" title="selected_metric.py" meta="{4-6}" />

   Append a request for two streets in a deliberate order:

   ```python title="selected_metric.py" {7}
   runner = LocalRunner.from_definitions({"city": selected_plugin()})
   tables = runner.run(
       "city_street_lengths",
       {"streets": {
           "collection": "example:city",
           "unit_type": "street",
           "ids": ["street-3", "street-1"],
       }},
   )
   print(tables["lengths"].to_dict("records"))
   ```

   Run `uv run python selected_metric.py`, or `uv run python -m city_example 2`. The output identifies `street-3` with length 300 m, followed by `street-1` with length 100 m. If you repeat an ID, Lyra includes that street once, at the position of its first occurrence. If an ID is unknown, execution fails with an error describing the failed lookup.

1. ## Test selection order and duplicate IDs

   Create `tests/test_selected_metric.py`. Request streets in a different order and repeat an ID:

   ```python title="tests/test_selected_metric.py" {10,13-14}
   from lyra.runtime.local import LocalRunner
   from selected_metric import selected_plugin


   def test_selection_preserves_first_occurrence_order():
       runner = LocalRunner.from_definitions({"city": selected_plugin()})
       table = runner.run("city_street_lengths", {
           "streets": {
               "collection": "example:city", "unit_type": "street",
               "ids": ["street-3", "street-1", "street-3"],
           },
       })["lengths"]
       assert table.street_id.tolist() == ["street-3", "street-1"]
       assert table.length_m.tolist() == [300.0, 100.0]
   ```

   Run `uv run pytest tests/test_selected_metric.py`. The test checks the resolved input order as well as the measured values.
