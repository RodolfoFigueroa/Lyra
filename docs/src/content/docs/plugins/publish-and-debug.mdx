Prepare your plugin so an operator can install it in a deployment image and enable it in configuration. Verify its package metadata and factory before sharing a tested version.

<Steps>

1. ## Check the package before handoff <span id="1-check-the-package-before-handoff"></span>

   Give your plugin its own distribution name and version in `pyproject.toml`. Declare `lyra[sdk]` and every other package your plugin imports directly. Use a synchronous factory that takes no arguments and returns a `PluginDefinition` containing all local nodes.

   Register an entry point so Lyra can find your factory. Name it `plugin` in the `lyra.plugins` group:

   ```toml
   [project.entry-points."lyra.plugins"]
   plugin = "your_plugin_module_here:create_plugin"
   ```

   Replace `your_plugin_module_here` with your plugin’s importable module name. Keep imports and factory calls free of service acquisition and handler execution.

   To inspect an installed package’s live definition, pass its distribution name to `load_installed_plugin_definition()`:

   ```python
   from lyra.sdk.loading import load_installed_plugin_definition

   plugin = load_installed_plugin_definition("your_plugin_distribution_here")
   ```

   Replace `your_plugin_distribution_here` with the installed distribution name. The loader normalizes package names and invokes only the selected distribution’s factory using installed metadata.

   Run [adapter and graph tests](../testing/). Check named outputs, producer-owned identifiers, and public serialization. Imports and inspection should work without initializing source services.

1. ## Inspect live definitions

   From the project directory, inspect the registered nodes and their dependencies:

   ```sh
   uv run lyra-plugin describe
   uv run lyra-plugin diagram --detailed
   ```

   Both commands load the registered factory without acquiring resources.

1. ## Share the package with the deployment owner <span id="4-share-the-package-with-the-deployment-owner"></span>

   Provide the package source or artifact, its pinned version, required data sources, and any deployment access requirements. Include the tests performed and any unresolved validation limits.

   Operators [add the plugin to the deployment image and configuration](../../operate/plugins/). Both API and workers must be able to import enabled plugins and their dependencies. The requested metric’s worker must have every transitive dependency plugin and source client available.

   Worker containers execute trusted plugin Python with their own permissions. Operators control which packages run and which secrets, mounts, and network access those workers receive.

   For a missing metric or queued job, use the [troubleshooting guide](../../operate/troubleshooting/).

</Steps>
