Use `lyra-plugin dev` to test your plugin through the local API and worker. The launcher installs your plugins in a separate uv environment. It uses the same Lyra checkout, Git commit, or release as your SDK.

## Start the city example <span id="develop-with-editable-sources"></span>

Install [uv and the Lyra SDK](../../start/installation/) on Linux, macOS, or Windows Subsystem for Linux (WSL). For the default setup, install Valkey and make sure `valkey-server` is on your `PATH`. You can also [use an existing Valkey server](#use-an-existing-valkey-server) without installing Valkey locally.

<Steps>

1. From the Lyra repository root, start the city plugin’s API and worker. The launcher starts a private Valkey server with an empty queue and stops it after the worker exits.

   ```sh
   cd examples/city-plugin
   uv run lyra-plugin dev
   ```

2. Leave that terminal open for API and worker logs. In another terminal, open the credentials file at the path the launcher prints. Use `LYRA_AGENT_API_KEY` from that file to [submit a city job](../../quickstart/#set-your-connection-details) at `http://127.0.0.1:5219`.

</Steps>

For your own plugin, install `lyra[sdk]` in its checkout and run `uv run lyra-plugin dev` there.

## Use an existing Valkey server

From your plugin checkout, pass the server’s URL to `--valkey-url`. After startup checks pass, the launcher **discards waiting jobs from this checkout’s queue**. Other queues on the server keep their jobs.

For a Valkey server running on your machine at port 6379, run this command. The server keeps running when you stop the dev session.

```sh
uv run lyra-plugin dev --valkey-url redis://localhost:6379/0
```

## Load your edits

Saving a Python file leaves the running services on the code they loaded at startup. When an edit changes results for the same inputs, update the affected node’s [`code_revision`](../../concepts/caching/#keep-cached-results-current) before restarting.

Press Ctrl-C once to stop submissions and let the worker finish its active job. Press Ctrl-C again if you want to interrupt that job.

Rerun `uv run lyra-plugin dev` to load your edits and synchronize dependency changes. The launcher keeps the uv environment and worker scratch files in a cache directory for each checkout. Your API keys and completed SQLite results persist there across sessions.

## Add another checkout

Stop the session, then relaunch with `--plugin` for each additional checkout. If your provider plugin lives in `../city-providers`, start both plugins together.

```sh
uv run lyra-plugin dev --plugin ../city-providers
```

Run the command in the primary plugin’s directory, or pass its path with `--project`. For an independent session, start a different primary checkout with `--port 5220`. Each checkout has its own waiting queue.

## Supply plugin settings and credentials

Pass `--resources resources.toml` to load the plugin’s [resource settings and credential references](../../operate/resources/). Specify relative credential file paths from the directory containing `resources.toml`. Export any referenced environment variables before starting the session.
